# IfPlay AI 小游戏生成平台

IfPlay AI 面向不会编程的普通用户和内容创作者。用户用中文描述游戏想法，AI 推荐合适的玩法组合，用户确认后生成可在手机浏览器直接游玩的轻量小游戏。

> 当前处于 MVP 验证阶段，下一步进行 OpenGame 接入验证，尚未提供可公开使用的在线产品。

## 产品方向

受控生成轨道首批规划四类主玩法：

- 经营模拟
- 拖拽合成
- 点击时机
- 剧情问答

每款受控游戏只有一个主玩法，最多组合两个辅助模块。平台采用双轨生成：常见玩法使用“统一运行时 + 白名单玩法模块 + `GameBundle`”；模块无法合理覆盖的新玩法进入隔离的代码生成、构建、测试和审核流程。

## AI 在哪里使用

- 理解用户的自然语言想法并补充关键信息。
- 推荐主玩法与辅助模块，生成方案卡供用户确认。
- 判断采用受控生成、实验生成还是暂不支持，并说明限制和成本。
- 把确认后的方案转换成结构化 `GameBundle`。
- 在实验轨道中生成独立游戏包，并在隔离环境完成构建、测试和有限次数修复。
- 生成角色、物品、订单、事件、对话、数值和结局等内容。
- 将自然语言修改转换为经过校验的配置补丁。
- 根据自动试玩结果修正可安全调整的配置问题。
- 为公开作品生成标签、摘要并进行内容风险初筛。

受控游戏由经过测试的运行时和玩法模块执行。实验游戏只能在隔离环境生成和验证，通过安全检查后进入私有试玩。

## 当前 M0

M0 先验证同一套运行时能否承载两种明显不同的玩法：

- 核心模块化运行时与 `GameBundle v0.2`
- 经营模拟模块
- 点击时机模块
- `localStorage` 存档与固定 seed
- 必要的自动测试和手机竖屏试玩页

两款手写样例：

1. 《我在三线城市给外星人修手机》
2. 《在公司厕所偷偷修仙》

M0 不接入 AI、后端、数据库、账户、发布、审核或游戏厅。先证明游戏结构和交互可复用，再进入 AI 生成阶段。

## 路线图

| 阶段 | 目标 |
| --- | --- |
| M0 | 核心运行时、经营模拟、点击时机和两款手写样例 |
| M1 | 增加拖拽合成、剧情问答和正式兼容矩阵 |
| M1.5 | OpenGame 接入验证、5 款多类型游戏、隔离执行和成本测量 |
| M2 | 接入 AI 创作、方案确认、结构化生成、修改和版本恢复 |
| M3 | 账户、审核、发布、游戏厅、社区和小规模公开测试 |

## 项目状态

- 产品市场：中国大陆
- 主要体验：手机竖屏网页，同时兼容电脑浏览器
- 首轮测试：计划邀请 10～20 人
- 测试期成本目标：每月增量成本控制在 100 元以内
- 商业化：首版免费，后续预留额度与支付能力

## 仓库说明

本仓库当前以产品方案、技术边界和阶段文档为主。M0 技术方案确认后再开始写代码，避免旧的单一模拟器架构影响新版方向。
