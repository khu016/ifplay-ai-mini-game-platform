# M2 后端第一阶段 · 证据包（验收说明）

- 日期：2026-10-03

## 一、照着做（产品经理接口验证步骤）

1. 启动后端（终端）：

```bash
cd apps/ifplay-backend
uv run uvicorn app.main:app --port 8000
```

看到 `Application startup complete.` 即成功。

2. 健康检查（新终端）：

```bash
curl -s http://127.0.0.1:8000/api/v1/health
```

看到 `{"status":"ok",...,"provider_is_real_model":false}` 即成功（false = 非真实模型）。

3. 创建创作会话：

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/sessions \
  -H 'Content-Type: application/json' \
  -d '{"idea":"开一家深夜食堂，经营小餐馆"}'
```

看到返回里 `status:"clarifying"`、`task_status:"clarifying"`，且 `clarifications[0].question` 是澄清问题，即成功。记下 `session_id`。

4. 提交两次澄清答案（把 `<sid>` 换成上一步的 session_id）：

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/sessions/<sid>/clarifications \
  -H 'Content-Type: application/json' -d '{"answer":"赚钱并升级"}'
curl -s -X POST http://127.0.0.1:8000/api/v1/sessions/<sid>/clarifications \
  -H 'Content-Type: application/json' -d '{"answer":"一局约5分钟"}'
```

第二次后返回 `task_status:"plan_ready"`。

5. 获取方案卡：

```bash
curl -s http://127.0.0.1:8000/api/v1/sessions/<sid>/plan
```

看到 `primary_module:"business"`、`track:"gamebundle"` 即成功。

6. 确认方案卡：

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/sessions/<sid>/plan/confirm
```

返回 `task_status:"confirmed"`。

7. 创建生成任务（幂等 key 可任意填；返回 202 + queued，不等待生成结束）：

```bash
curl -i -X POST http://127.0.0.1:8000/api/v1/sessions/<sid>/tasks \
  -H 'Content-Type: application/json' -d '{"idempotency_key":"demo-1"}'
```

看到 `HTTP/1.1 202` 且 body 里 `status:"queued"` 即入队成功。后台工作器会自动领取并生成。记下 `task_id`。

8. 查询任务状态（稍等 1～2 秒，工作器完成后应为 playable）：

```bash
curl -s http://127.0.0.1:8000/api/v1/tasks/<task_id>
```

看到 `status:"playable"` 即生成完成。若仍为 `queued/generating`，再查一次。

9. 查询结果与校验摘要：

```bash
curl -s http://127.0.0.1:8000/api/v1/tasks/<task_id>/result
```

看到 `validation_summary` 五项全部 `passed:true`，且 `version.version_number:1`、`usage` 记录了 token/费用。

10. 查询版本列表：

```bash
curl -s http://127.0.0.1:8000/api/v1/sessions/<sid>/versions
```

11. 恢复历史版本（把 `<version_id>` 换成版本列表里的 id）：

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/versions/<version_id>/restore
```

返回新版本，`parent_version_id` 指向被恢复版本。

12. 服务重启验证：Ctrl+C 停掉后端，再执行第 2 步命令启动，然后重复第 8/9 步，数据仍在（SQLite 持久化）。若停在后端时任务正处 `generating/validating`，重启后变为 `interrupted`，需 `POST /tasks/<task_id>/resume`（body 含 `idempotency_key` 和 `confirm_retry:true`）恢复。
