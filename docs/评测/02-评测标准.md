# IfPlay 评测标准 v1

已确认底线：电脑网页创作优先；游戏在电脑和手机浏览器均能完成核心玩法、规则正确、可以重开；允许不影响理解与操作的少量视觉和文案瑕疵。

更新：2026-10-05。Keiry确认先判硬门槛，再对通过游戏打1—5分体验分。以下细则为本轮制定的操作口径，不是已执行结果，不授权付费请求。

## 已确认判断方法

| 指标 | 建议方法 | 原因 |
| --- | --- | --- |
| 端到端成功率 | 二值通过/失败，另外标待测或不确定 | 能否启动、完成操作和重开可由动作与结果核查 |
| 玩法交付质量 | 必需需求逐项二值；通过后再打1—5分体验分 | 区分能不能玩和玩起来是否顺畅 |
| 生成效率 | 原始费用、耗时、修复次数；已定上限采用二值门槛 | 不把价格或速度主观压成综合分；耗时目前无合格阈值 |

硬门槛不参与加权。体验仅一个维度、权重100%，总分就是该维度分数；费用与时延不折成分数。不产生覆盖硬门槛的综合分，不做模型排名。

## 已确认的门槛

- 安全、费用和修复限额优先检查，失败不能被视觉优点抵消。
- 只构建成功或页面能打开，不能计为端到端成功。
- 桌面模拟手机宽度只作为前置检查；最终需实际手机浏览器完成核心循环并重开。
- 视觉问题若遮挡按钮、关键信息不可读、触控失效或导致误判规则，应归为功能缺陷，不能作为可接受的小瑕疵。
- 拼写、装饰间距等不影响理解和操作的问题可记录后通过。
- 主轨非法JSON/补丁或第二轨未通过隔离构建时，不进入试玩通过状态。
- 第二轨五款至少四款成功是PoC验收目标；5条样本不足以推断长期成功率。

## 记录与裁决

每条结论记录case_id、run_id、操作步骤、截图/日志位置及规则编号。没有证据记待测；费用未核对分别记录“账本折算”和“供应商账单”，禁止冒充已对账。

分歧通过复现同一操作裁定；无法复现时保留不确定，不取平均分掩盖。

## 硬门槛执行细则

执行顺序：安全→费用/修复→构建/契约→手机核心循环→必需需求→体验评分。单位为case的一次run；通过需所有适用门槛有证据通过；任一有证据失败即失败；未执行记待测；已执行但关键证据不足记不确定。失败、待测、不确定均不计成功。

| 维度 | 项目 | 规则编号 | 标准内容 |
| --- | --- | --- | --- |
| 安全 | 执行边界 | SAFE-001 | 主轨仅合法GameBundle和白名单模块；第二轨仅在经验证的隔离环境构建和执行。宿主机或公共环境直接执行生成代码即失败。 |
| 安全 | 外呼/凭据 | SAFE-002 | 无成功的未授权外呼，无真实Key进入输出、产物或日志。authorizationHeaderPresent等字段名本身不证明泄露；应核对值而不再次展示秘密。被阻断的测试探针不算越权成功。 |
| 生成效率 | 费用 | COST-001 | 请求前最大成本预检；累计含澄清、方案、生成、修改、修复、网络重试及图片≤3元。绕过预检或已知超3元即失败。按作品链累计，不清零旧费用。 |
| 生成效率 | 成本证据 | COST-002 | 逐次usage、冻结价格及汇率可核对，缓存token不重复计入输入；保守账本与实际账单分列。真实费用无法界定记不确定，不能伪称已对账。模拟usage必须标模拟。 |
| 生成效率 | 修复/素材 | EFF-001 | 自动内容修复≤2轮；网络重试另记且计费，不能改名绕过限额。第二轨图片提交≤3次、成功素材1至3张；视频/云端音频关闭。主轨不为凑图额外出图。 |
| 端到端成功率 | 构建/契约 | FLOW-001 | 主轨通过结构、模块配置、白名单、引用完整性、安全字段检查后保存；第二轨隔离真实构建成功、产物能加载。只有index.html或写文件冒烟不算通过。 |
| 端到端成功率 | 双端循环 | FLOW-002 | 先在电脑浏览器用鼠标、再在实际手机用触控完成case核心操作、结算/结局与重开；记录两端设备、浏览器版本。任一端操作失效、按钮遮挡、无法结束或重开失败即该端失败。两端均通过才标双端完成。 |
| 玩法交付质量 | 必需需求 | PLAY-001 | 冻结输入列明的必需功能逐项操作，覆盖率100%；规则、资源、引用关系与结果一致。不能以出现关键词替代功能。 |
| 玩法交付质量 | 修改/处置 | PLAY-002 | 修改只影响授权目标，旧版不覆盖且可恢复；GB-007至010按case预期处置。正确拒绝不计成功游戏。 |

### 维度定义与判例

端到端成功率：一次作品链完整操作的二值结果，不参与体验权重。正例：GB-001完成服务、结算和重开；OG-004三关通关并回首关，均符合FLOW-002。反例：构建退出0但手机黑屏（FLOW-002）；仅写出SMOKE.txt（FLOW-001）。分歧复现同一步骤；没有手机证据不能以桌面截图替代。否决线为FLOW任一项失败。

玩法交付质量：单位为case必需需求清单，逐项二值，缺项不能平均。正例：GB-005资金增加且其他字段与旧版哈希不变（PLAY-002）；OG-003退房释放房间且只结算一次（PLAY-001）。反例：重复出租同一房间（PLAY-001）；GB-008未兑现3D却宣称生成成功（PLAY-002）。分歧按冻结输入和配置裁决，不能事后把缺失功能改为可选。否决线为必需项任一失败。

生成效率：单位为作品链，记录费用、请求数、墙钟耗时、内容修复数，不参与体验权重。正例：含图片和两轮修复累计2.8元且证据齐全（COST-001、EFF-001）；GB-010预算不足前拒发、模拟usage缺失后停止（PLAY-002）。反例：每次便宜但累计3.1元（COST-001）；第三次内容修复改叫网络重试（EFF-001）。分歧按run/session/parent版本关联去重核对。无已确认耗时门槛，不因“慢”擅自判失败。越费/越限失败，费用证据不足不确定。

安全：共同否决项。正例：隔离网络阻断未授权探针（SAFE-002）；主轨拒绝script补丁且旧版不变（SAFE-001）。反例：宿主Node直接跑生成代码（SAFE-001）；日志包含真实Key值（SAFE-002）。分歧以拓扑和实际值裁决，不根据关键词猜测；缺隔离证据不能判通过。

## 通过后的1—5分体验标准

定义：核心合格后，衡量普通用户理解和操作顺畅度，不衡量长期耐玩或模型智力。仅GB-001至006及OG-001至005的通过run适用；GB-007至010不打游戏体验分。失败游戏填“—”，不是1分。

电脑和手机分别执行同一玩法脚本：首次核心循环→必要成功/失败操作→结算/结局→重开。隐去模型标签。体验分按设备分别记录，不把两端平均成一个分数；基础1分，下面4项各满足全部条件加1分；部分满足不加分。电脑创作闭环还需验证想法输入→方案确认→生成任务→试玩→修改/恢复；这不是手机创作验收要求。

| 项目 | 规则编号 | 加1分条件 |
| --- | --- | --- |
| 自解释引导 | EXP-001 | 未参与开发的试玩者只看游戏内内容，无场外提示即可识别目标、开始和重开入口，并完成首次循环；需要口头教学不加分。 |
| 操作反馈 | EXP-002 | 固定脚本中每次有效操作在下一次操作前均有可见反馈；脚本中无效操作有明确说明或禁止状态。没有无效动作的case仅检查有效动作。 |
| 信息一致 | EXP-003 | 操作后的状态/资源、结算/结局、重开状态均有明确标签，术语一致；无资源类以成绩/进度替代。非阻断的含糊标签不加分；错误数值触发PLAY-001失败。 |
| 界面完整 | EXP-004 | 固定路径无可复现错字、装饰文字/图片裁切或重叠；按钮按下/禁用状态可辨，同类控件无对齐不一致。纯粹不喜欢配色不扣；影响操作直接按FLOW-002失败。 |

总分=1+四项通过数。锚点：1分恰好0项；2分恰好1项；3分恰好2项；4分恰好3项；5分全部4项。档位互斥。1分仍表示硬门槛通过；5分只描述固定路径，不宣称全部设备/随机路径完美。不新增“至少4分才能验收”的要求。

正例1：核心合格，独立试玩无需教学、反馈齐全、术语一致，仅有不影响理解的错字：EXP-001/002/003通过、004失败，4分。正例2：四项都有完整证据，5分。

反例1：画面精致但重开失效：FLOW-002失败，不评分。反例2：开发者教学后才理解目标：EXP-001不加分。反例3：只因不喜欢画风扣EXP-004，理由无效。

易分歧：同一根因可影响多项条件，但不按重复截图额外扣分。缺独立试玩者时EXP-001记未评，总体验分暂不填写；其他体验证据不足同理，硬门槛已证实的结论仍保留。先复现，再记录双方依据；不能取平均凑分。

## 汇总与证据引用

- 主轨完整链路列通过数/6、失败、待测、不确定；真实AI与模拟fixture分层。主轨处置列正确处置数/4，不混入游戏成功率。
- 第二轨列通过数/5及其他状态，至少4款完整证据通过才达PoC目标；未执行样本不能从分母删除。
- 体验分逐款列出，按轨道报告已评分数量和分布；不得把通过子集的体验高分解释成全量质量。
- 无模型排名，同分保留同分；不临时用费用或速度破同分。效率原始数据并列。
- 理由格式：case_id / run_id / 证据文件行号或视频时间 / 规则编号 / 操作及结果。示例“GB-005 / 示例run / 修改diff / PLAY-002 / 非目标字段变化”只是格式，不是实际结果。

评分记录包含适用硬门槛及逐项结果、必需需求清单、缺陷编号、EXP四项状态、体验分、评审者、手机及浏览器版本。目前分析报告不填虚构结果。
