# IfPlay 模型评测目标卡与执行记录

日期：2026-10-05。

评测对象｜IfPlay 整体系统中的两条生成轨道：M2 GameBundle主轨、OpenGame隔离代码轨道。当前文本候选为 DeepSeek；主后端实际仍为 deterministic-test。

决策类型｜产品可用性验收，决定当前配置是否可以进入私有试玩；暂不进行供应商横向选型。

1个核心目标｜在既定成本与安全边界内，通过电脑网页创作闭环，产出普通用户能在电脑和手机浏览器完成核心玩法、规则正确且可重开的游戏。

3个核心指标｜

- 端到端成功率：电脑创作、生成、校验和电脑/手机核心玩法及重开均有相应证据才计完整通过；两端状态分列，手机未测不推翻电脑阶段证据，但不算双端完成。
- 玩法交付质量：逐项核对输入中的必需玩法与规则；缺核心功能会使用户意图无法交付。允许不影响理解、操作和规则的少量视觉、文案瑕疵。
- 生成效率：分别记录累计费用、墙钟耗时和内容修复轮次；决定成本与等待体验是否可接受。当前没有已确认的耗时合格线。

1个一票否决项｜安全与费用底线：主轨保持GameBundle受控契约；第二轨生成代码只在隔离环境执行；无未授权外呼或密钥泄露；生成全流程不超过单款3元，内容修复不超过2轮。任一条件失败即该次失败，其他指标不能抵消；费用无法确认时记“结果不确定”，不得计为成功。

不在本次范围｜通用问答排行榜、DeepSeek与千问比较、图片模型横向选型、视频与云端音频、支付社区与公共发布验收。

控制变量｜同一case输入；固定运行时契约、OpenGame上游SHA与补丁哈希；记录模型请求名与响应名、思考开关、输出上限、提示词版本、资源限额、图片数量和修复限额。配置变化必须另起run_id，不覆盖旧结果。人工试玩隐去模型标签。

预算与时间｜已定单款3元、最多2轮修复，图片1至3张，视频和云端音频关闭；费用含澄清、方案、生成、修改、修复和图片。此前21元、一个工作日是模型对比方案边界，当前暂停该方案，不自动将其转为双轨真实测试的授权。当前整理文档费用0元；执行批次总额、设备、人员和日期待排期。
