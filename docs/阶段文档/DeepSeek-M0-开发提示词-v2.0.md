## 二、你对产品的理解

IfPlay AI 是面向不会编程的大众和内容创作者的 AI 小游戏生成平台。用户以后会用中文描述想法，AI 推荐玩法组合并生成结构化游戏配置。游戏必须由平台白名单模块运行，AI 不生成和执行任意代码。

首版规划有四类主玩法：

1. 经营模拟。
2. 拖拽合成。
3. 点击时机。
4. 剧情问答。

每款游戏只能有一个主玩法，最多两个辅助模块。

本轮只做 M0：核心模块化运行时、经营模拟模块、点击时机模块和两款手写样例。拖拽合成、剧情问答、AI 接入、后端、数据库、账户、发布和游戏厅都不在本轮开发范围。

## 三、M0 技术目标

用一个 TypeScript 网页项目证明：

- 同一套核心运行时可以加载不同 `GameBundle`。
- 经营模拟和点击时机是两个遵守统一契约的模块。
- 两款题材差异明显的游戏无需修改引擎代码即可运行。
- 游戏支持固定 seed、重新开始、暂停恢复和 `localStorage` 存档。
- 关键逻辑可自动测试，浏览器中能完成一轮核心玩法。

## 四、M0 样例

### 样例一：《我在三线城市给外星人修手机》

- 主玩法：经营模拟。
- 核心循环：接待外星顾客 → 判断需求 → 选择零件与报价 → 修理 → 结算 → 升级。
- 关键状态：资金、库存、耐心、口碑、能量电池。
- 必须验证：队列、收入支出、库存、随机事件、升级、存档和至少两个结局。

### 样例二：《在公司厕所偷偷修仙》

- 主玩法：点击时机。
- 核心循环：观察巡查信号 → 在安全窗口点击运气 → 管理灵气、憋气和暴露度 → 完成小周天 → 解锁功法。
- 必须验证：点击窗口、连击、资源变化、暂停恢复、结果档位、存档和至少两个结局。

两款样例都要保持原创、抽象和无厘头，不使用真实人物、公司、影视角色或品牌，也不要照搬热梗文本。

## 五、架构约束

### 1. GameBundle

设计 `GameBundle v0.2`，至少包含：

- manifest
- experience
- scenes
- primaryModule
- auxiliaryModules
- entities
- rules
- progression
- uiLayout
- assets
- saveSchema
- testPlan

先写清类型、JSON Schema 或等价校验规则，再写运行逻辑。字段需要有用途，不要为未来预留大量空结构。

### 2. 核心运行时

需要提供状态存储、回合或可暂停时钟、seedable RNG、事件总线、白名单条件和效果执行器、场景路由、输入归一化、存读档与迁移版本，以及资源加载失败降级。

### 3. 玩法模块契约

经营模拟和点击时机模块都必须通过统一契约接入。契约至少说明：

- 模块 ID 和版本。
- 配置校验。
- 生命周期。
- 输入。
- 可读写状态。
- 白名单事件。
- 渲染接口。
- 测试适配器。

### 4. 安全边界

- 禁止 `eval`、`Function`、脚本字符串和动态远程代码。
- `GameBundle` 只能包含数据和白名单枚举指令。
- 样例专用内容只能放在配置中，不能在引擎里写题材专用条件。

## 六、测试要求

只写能验证架构风险的测试：

- `GameBundle` 结构、引用完整性和非法配置拒绝。
- 固定 seed 得到可复现结果。
- 存档与恢复。
- 经营模拟的队列、收支、库存和可达结局。
- 点击时机的判定窗口、连击、资源和结束条件。
- 两款样例能在浏览器中完成一轮玩法的冒烟测试。

不要为简单样式或实现细节写重复测试。

## 七、界面要求

M0 只做最简可验证界面：

- 一个样例选择页。
- 两个游戏的可玩页。
- 开始、暂停、继续、重新开始、存档和读档。
- 显示当前核心状态和游戏反馈。
- 手机竖屏可操作，同时兼容电脑浏览器。

不做正式品牌视觉、登录、社区、发布、AI 生图和复杂编辑器。
