# PRD 补全清单

> 项目：IfPlay AI 模拟器游戏平台 · PRD v1.1（2026-09-28）
> 体检结论：PRD 已高度完整（相当于已完成产品访谈）。「必须问」仅剩 3 项，其余缺口按默认值补齐待确认。

## 必须问（本轮 3 个）

### 问题 1：云厂商账号与 API Key 现状
- 为什么重要：PRD 指定了阿里云百炼（qwen + 万相生图）、腾讯云（内容审核 + 短信）多家厂商，直接决定阶段 2 能否真实冒烟、费用由谁承担。
- 选项：A 已有其中某家账号/Key（请告诉我是哪家）；B 都没有，希望先按 PRD 推荐去开通阿里云百炼；C 都没有，先不用真实 Key、用 mock 推进，真实 Key 到阶段 2 冒烟前再给。
- 推荐：C。阶段 0/1 不花钱、用 mock 推进；真实 Key 到阶段 2 真实冒烟前再给，避免现在就开通账号产生不必要的操作和费用。
- 不选的后果：选 A/B 需要你额外去控制台开通和付费；若开通后才发现额度/价格不符，会返工。

### 问题 2：首个交付切片范围
- 为什么重要：MVP 有 M0–M3 四个里程碑，一次全做违反"核心链路先验证"规则，也拉长验收周期。
- 选项：A 先做最小可玩闭环（M0 规则引擎 + M1 AI 生成闭环：想法→澄清→方案卡→生成 GameSpec→试玩→修改/版本），账户/发布/社区后置；B 按 M0→M1→M2→M3 逐里程碑推进，每个里程碑单独验收；C 一次性做到 M3 再验收。
- 推荐：B（本质是 A 的落地方式）。先交付"想法→可玩→可改"闭环并真实冒烟，再逐层加账户发布和游戏厅，每层独立验收。
- 不选的后果：选 C 一次铺开，核心链路未验证就做账户/审核/社区，问题集中爆发、难以定位；选 A 若不做里程碑切分，边界容易模糊。

### 问题 3：封闭测试部署环境与费用归属
- 为什么重要：100 元月预算里"存储与测试部署仅 20 元"，但封闭测试要 10–20 人可访问的对外环境，20 元很可能不够，需先讲清谁出、怎么出。
- 选项：A 开发期本机验证，封闭测试部署到阶段 4 再按实际费用单独确认（不挤占 100 元生成预算）；B 封闭测试就用某低成本云/免费额度，费用仍从 100 元内出；C 另行给一个部署预算额度（请告知金额）。
- 推荐：A。先把 100 元守住用于模型/生图/审核/短信；部署环境到阶段 4 按实际报价单独确认，避免现在低估导致超支或服务中断。
- 不选的后果：选 B 可能封测中途部署费用挤爆生成预算，触发 100 元硬上限停止生成；选 C 需要你现在就定一个数。

## 已发现的矛盾（如有）
- 矛盾点 1：100 元月预算中"存储与测试部署仅 20 元"，与"10–20 人封闭测试需对外可访问环境"可能冲突。→ 推荐裁决：见必须问问题 3，开发期本机验证、封测部署费用单独确认。
- 矛盾点 2：5.2 指标（≥70% 成功生成、≥85% 技术完成率等）在 10–20 人 / ≤30 款样本下统计意义有限。→ 推荐裁决：按 PRD 原文作为"测试后校准"的初始目标，不当作硬验收线；质量线用真实样例打分补。
