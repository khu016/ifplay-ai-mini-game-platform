# 技术适配声明

> 项目：IfPlay AI 模拟器游戏平台 · 阶段 1 技术适配
> 日期：2026-09-28（按产品经理修正更新）
> 依据：PRD v1.1 + 通用技术栈手册第一部分（一至六节）+ 产品经理 2026-09-28 修正意见

## 1. 产品形态判断
- 产品类型与核心任务：AI 生成游戏平台（UGC + Agent 生成可玩模拟器）。用户用中文描述任意题材 → AI 澄清 → 方案确认 → 生成版本化 `GameSpec` → 固定引擎运行成可玩模拟器 → 修改/版本回退 → 发布/审核/做同款。
- 核心交互：分阶段确认（澄清对话 + 方案卡确认门）+ 多轮对话修改 + 后台任务分阶段生成 + 浏览器试玩（人工确认、可视化操作）。
- 开发路径：**纵向切片**（试玩、方案确认、修改属于"交互即 Agent 能力"，需真实交互端到端验证）。
- 当前阶段范围：**仅 M0 规则引擎验证**（固定 GameSpec、规则引擎、校验器、自动路径模拟、结局可达性、3 个手写示例、最简试玩页）。**不调用真实模型、不产生费用**；M1（AI 生成闭环，接 DeepSeek）在 M0 验收通过后单独推进。

## 2. 采用的默认方案
- 规则引擎与前端：**TypeScript（纯前端单包，Vite 构建）**——游戏在浏览器运行，引擎需确定性执行 + 可测试 + 可复用，TS 一份代码同时跑 Node 测试与浏览器。
- 校验：TypeScript 类型 + 运行时白名单校验（GameSpec 严格 schema）。
- 测试：Vitest（Node 共享引擎源码）+ Playwright（浏览器冒烟）。
- 代码管理：Git（沿用外层仓库，本目录不重复 init）。
- 后端与数据库：**M0 不引入**（无账户/无模型/无多用户；localStorage 存档）。M1 再引入后端（倾向 TS 轻量后端，见第 4 节）。

## 3. 触发的按需模块
| 模块 | 触发需求 | M0 是否引入 |
| --- | --- | --- |
| 规则引擎 + seedable PRNG | 确定性执行、同 seed 同路径 | 是 |
| 结构化校验 | GameSpec 严格校验、禁止脚本字段（ENG-11） | 是 |
| 规则模拟器 | 自动试玩：推进、死局、资源越界、结局可达（QA-03/04） | 是 |
| 浏览器冒烟测试 | 首屏/开始/选择/存档/恢复（QA-05） | 是 |
| 关系型数据库（SQLite） | 版本/任务持久化 | **否**（M1 引入；M0 用 localStorage） |
| 长耗时任务持久化 / SSE | 生成任务进度 | **否**（M1 引入） |
| 大图片/生成文件 | 封面/关键图 | **否**（生图暂缓，默认模板） |

## 4. 偏离或暂缓的默认方案
| 项 | 替代/暂缓 | 原因 | 影响 | 重新评估条件 |
| --- | --- | --- | --- | --- |
| 后端语言 Python/FastAPI（手册默认） | M0 **纯 TypeScript 前端、无后端**；M1 后端语言届时再定（倾向 TS 轻量后端，必要时回退 Python/FastAPI） | M0 无模型/账户/多用户，后端属"需求未触发的模块"；引擎需与前端同栈避免双实现漂移 | M0 无需后端；M1 引入后端时再定语言 | M1 引入后端时 |
| 关系型数据库 | M0 不建库，localStorage 存档 | M0 单机试玩，无持久化服务需求 | 存档不跨设备 | M1 版本/任务持久化时 |
| 文本模型厂商 | M1 用 DeepSeek（用户已持有 Key），M0 不调用 | 用户指定；M0 用手写/mock 数据 | M0 零模型费用 | M1 开工时 |
| 生图 / 内容审核 / 短信 | 暂缓（默认模板 / 后置） | 用户确认暂缓；M0/M1 无发布 | 封面用默认模板 | M2 前确认 |
| 正式前端（Next.js） | M0 用最简试玩页（功能页，无视觉设计） | 核心能力未验证前不铺正式前端 | 阶段 3 再上正式前端 | M0/M1 验收通过后 |

## 5. 强制底线检查
- 密钥与隐私：**通过（M0 无密钥）**；M1 起 DeepSeek Key 由用户填 `.env`，不回显、不进仓库/前端。
- 数据与任务可恢复：**通过（M0 无服务端数据）**；M1 起 SQLite 持久化并实测重启恢复。
- 输入输出校验：**计划中**（M0 起 GameSpec 白名单校验，禁止脚本字段）。
- 错误与日志边界：**计划中**（统一错误结构；日志不记敏感信息）。
- 测试与真实模型验收：M0 全 mock 测试（不产生费用）；M1 起 DeepSeek 真实冒烟；质量线 D2 待样例打分。

## 6. 需要产品经理决定的问题
- 无阻塞项。待定项（D2 质量线/D3 瑕疵容忍度待样例打分、D9 上线主体阶段 4 前确认、生图/审核/短信 Key 到 M2 前确认）均不影响 M0。
- M0 开发前仍需产品经理确认三项（已在《第一阶段技术开发文档》第十四节列出）：三个手写示例题材、M0 纯前端无后端无数据库、试玩页最简程度。
