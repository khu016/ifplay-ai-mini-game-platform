## 7. `GameBundle v0.2` 最小类型

> 原则：先定义 Zod 校验规则，再由 `z.infer` 派生类型；字段有实际用途，不为未来预留空结构。校验在 `core/schema.ts`（`z.config({ jitless: true })` 已生效）。

```ts
type ModuleId = 'business' | 'timing';

interface GameBundle {
  manifest: Manifest;              // id / name / version / author / language / runtimeVersion
  experience: Experience;          // playerRole / goal / estimatedMinutes / difficulty / intro
  scenes: Scene[];                 // id / type(menu|play|result) / layoutId
  primaryModule: PrimaryModule;    // id(ModuleId) / version / config(按模块收窄)
  auxiliaryModules: AuxiliaryModule[];  // M0 恒为空，保留契约一致
  entities: Entity[];              // 角色/顾客/物品/订单/资源等题材对象
  rules: Rule[];                   // when(白名单条件) / then(白名单效果)
  progression: Progression;        // tasks / upgrades / endings(≥2)
  uiLayout: UiLayout;              // theme / playLayout
  assets: Assets;                  // placeholder / icons?
  saveSchema: SaveSchema;          // version(正整数) / keys(状态键白名单)
  testPlan: TestPlan;              // cases
}
```

校验要点：`primaryModule.id` 命中注册模块；`config` 按模块 id 用对应 Zod schema 校验；引用完整性；数值范围；文本与对象数量上限；`auxiliaryModules ≤ 2`；`endings ≥ 2`；`saveSchema.version` 正整数、`keys` 非空且在白名单内。

## 8. 核心运行时与模块契约

- **运行时**：seedable RNG（mulberry32）、不可变状态 + 变更追踪、回合/可暂停时钟、事件总线、白名单条件/效果执行器、场景路由、输入归一化、`localStorage` 存读档 + 版本迁移、资源加载降级、ViewModel 原语、运行时组装生命周期。
- **模块契约**：`id + version`、`validateConfig`、`createInitialState`、纯函数 `reduce`/`tick`、`serialize`/`deserialize`、`view`（输出 ViewModel）、`testAdapter`；模块只消费归一化输入、只读写自己状态、事件走白名单。
- **职责边界**：RNG/时钟/事件/存读档/输入/场景/素材/ViewModel → 运行时；玩法规则与模块私有状态 → 模块；题材文案数值 → 只进 `bundles/`。

## 9. 两款样例只通过配置运行

每个样例是纯数据 `GameBundle`（无函数）。运行时 `createGame(bundle)`：`schema.validate` → 按 `primaryModule.id` 查模块注册表 → 模块 `validateConfig` → `createInitialState` → 进入 `play`，此后不再区分"是哪款游戏"。题材差异全部体现在 `entities`/`rules`/`progression`/`experience` 的文案与数值。护栏：扫描测试断言 `core/`、`modules/` 源码不含两个游戏名及关键词；新增第三款经营游戏只需新增 bundle，引擎零改动。

## 10. 测试方案和验收标准

### 10.1 自动化测试

| 层级 | 内容 | 工具 |
| --- | --- | --- |
| 单元 | schema 校验、rng 可复现、save 存读档与迁移、effects 白名单命中/拒绝 | Vitest |

### 10.2 验收标准（M0 通过条件）

1. 两款样例都能在**手机竖屏**与电脑浏览器各完成一轮核心玩法。
2. 同一引擎加载不同 `GameBundle` 即可切换游戏，无需改引擎。
3. 引擎与模块源码不存在题材专用分支（扫描测试为准）。
4. 存档、读档、重新开始、暂停恢复、固定 seed 全部有效；**相同 seed + 相同操作 → 相同结果**。
5. **刷新页面后能恢复存档**。
6. 全部自动化测试 + 浏览器冒烟（含竖屏）通过；`tsc --noEmit`、ESLint、`vite build` 通过。
7. 不使用 `eval` / `Function` / `new Function` / `z.compile()` / 脚本字符串 / 动态远程代码。
8. 不接入 AI、后端、数据库、登录、发布、审核、游戏厅；不新增大型游戏框架；除 Zod 外不新增运行时依赖。
