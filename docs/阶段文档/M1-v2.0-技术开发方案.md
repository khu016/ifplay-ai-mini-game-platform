# M1 v2.0 技术开发方案

> 对应 PRD：`PRD-IfPlay-AI小游戏生成平台-MVP-v2.0.md`（§11 M1）
> 前置：M0 已验收（统一运行时 + business/timing + 两款样例 + 存读档 + 固定 seed）
> 状态：已确认，进入 M1 开发

---

## 1. 范围

在 `apps/ifplay-m0/` 内**继续开发，不重写 M0**，新增两种玩法模块，使平台共有四种主玩法：

| 模块 ID | 玩法 | M0/M1 |
| --- | --- | --- |
| `business` | 经营模拟 | M0 已验收 |
| `timing` | 点击时机 | M0 已验收 |
| `drag-merge` | 拖拽合成 | M1 新增 |
| `story-quiz` | 剧情问答 | M1 新增 |

新增两款原创样例（纯 GameBundle 配置）：

1. 《把老板画的饼拖进微波炉炼成年终奖》（drag-merge）
2. 《凌晨三点在业主群竞选小区龙王》（story-quiz）

不接入 AI、后端、数据库、账户、发布、审核、生图、游戏厅；不整站视觉重做。

## 2. 数据结构

### 2.1 GameBundle 兼容扩展（v0.2 → v0.3，向后兼容）

- `manifest.runtimeVersion` 接受 `'0.2' | '0.3'`。M0 两款 bundle 保持 `0.2`；新增 bundle 使用 `0.3`。
- `primaryModule.id` 白名单扩展为 `business | timing | drag-merge | story-quiz`。
- `progression.endings[].condition` 改为**可选**：business/timing/drag-merge 用通用条件（`resourceReached` 等），story-quiz 用叙事触发（节点/选项直接引用 ending id），无需条件字段。
- 其余字段与 M0 一致，`z.config({ jitless: true })` 保持不变；禁止 `eval`/`Function`/`new Function`/`z.compile()`。

### 2.2 drag-merge 配置结构（Zod）

```ts
{
  labels: { score, steps, combo },
  maxSteps: number, targetScore: number,
  wrongPenalty: number, comboMultiplier: number,
  items: [{ id, name }],                         // 可拖动物品
  slots: [{ id, name }],                         // 放置区（容器）
  initialItems: Record<itemId, count>,
  recipes: [{ id, name, inputs: Record<slotId, itemId>, score, resultName, flag? }],
}
```

状态：`{ score, step, combo, inventory, slots, produced[], flags, ... }`。dnd-kit 只负责拖拽输入；合法性判断、配方、得分、步骤限制、结局全部由确定性模块逻辑处理。

### 2.3 story-quiz 配置结构（Zod）

```ts
{
  labels: { score, ... },
  attributes: [{ id, name }],
  startNodeId: string,
  nodes: [{
    id, text, speaker?,
    choices: [{
      id, text,
      effects?: [{ type: addAttribute|addScore|setFlag|addFlag, ... }],
      next?: nodeId, condition?: { type, params }, once?: boolean, ending?: endingId,
    }],
    ending?: endingId,
  }],
}
```

状态：`{ currentNodeId, attributes, score, flags, usedChoices[], history[], ... }`。校验器拒绝：悬空引用、无出口节点、不可达节点、无法到达任何结局的节点（防无限循环）。

## 3. 模块契约（复用 M0）

两个新模块继续实现 `GameplayModule` 契约（`id/version/validateConfig/createInitialState/reduce/tick?/serialize/deserialize/view`），由统一运行时按 `primaryModule.id` 从注册表调用。题材、文案、数值、素材只在 GameBundle 配置；模块源码不得含示例专用判断。

## 4. 兼容策略

- `runtimeVersion 0.3` 相对 `0.2` 是**向后兼容扩展**：只增加模块白名单与可选字段，不改变已有字段语义。
- M0 两款 bundle（`0.2`）无需改动即可继续运行；旧存档 `saveSchema.version` 不变（各模块存档键独立），读档失败仍退回新开局，不无提示损坏。
- 新增模块各自声明 `saveSchema.keys`，走运行时统一的 `localStorage` 存读档。

## 5. 依赖

| 包 | 官方地址 | 用途 | 许可证 | 版本 |
| --- | --- | --- | --- | --- |
| @dnd-kit/core | https://dndkit.com | 拖拽输入交互（仅 UI 层） | MIT | ^6.x |

> 仅新增 `@dnd-kit/core`；`@dnd-kit/utilities` 仅确有必要时引入。合成规则/得分/结局仍在模块纯逻辑中，不写进 React 组件。无 GPL/AGPL。

## 6. 测试

- 两个新模块的 Zod 配置校验（合法通过 / 非法拒绝）。
- 固定 seed 可复现（drag-merge 的初始物品与配方判定；story-quiz 无随机，确定性）。
- drag-merge：合法/非法放置、配方合成、得分、连击、步骤限制、成功/失败/隐藏结局。
- story-quiz：节点跳转、条件选项、flags、一次性选项、多结局与隐藏结局；悬空引用 / 无出口节点 / 不可达结局被拒绝。
- 新旧存档读档（M0 两款 + M1 两款）。
- 四款游戏均可开始、操作、存档、恢复、到达结局。
- 手机竖屏 390×844 与桌面 Chromium E2E；M0 回归通过。
- typecheck / lint / vitest / build / playwright 全部通过。

## 7. 验收标准

1. 平台共有四种主玩法，选择页展示四款游戏及玩法类型。
2. 四款游戏都能在手机竖屏与桌面各完成一轮核心玩法并到达结局。
3. 每款新游戏至少含普通成功、失败、隐藏结局。
4. 引擎与模块源码无题材专用判断（沿用 themescan）。
5. M0 两款游戏回归通过；旧存档可读。
6. 禁止动态代码执行；除 `@dnd-kit/core` 外不新增运行时依赖。
7. 证据放入 `apps/ifplay-m0/docs/evidence/M1/`。
