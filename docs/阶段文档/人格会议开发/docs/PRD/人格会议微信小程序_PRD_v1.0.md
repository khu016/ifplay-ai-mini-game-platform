## 1. 产品概述

人格会议是一款微信小程序。用户提出一个正在困扰自己的问题，系统推荐或由用户选择 3 至 5 个四字母人格类型作为参会角色。不同角色围绕同一问题持续讨论，用户可以随时插话、补充情况、追问某个角色或指定角色继续交流。用户结束会议时，主持人整理一份决策纪要。

产品主要服务习惯找 AI 聊天、咨询问题，并希望获得多角度回复的成年人。学生和年轻职场人是首批重点用户。

人格角色的作用是提供不同的关注角度。它们不代表真实专家或彼此独立的证据来源，也不用于判断用户的能力、心理状态或命运。最终决定始终由用户作出。

## 2. 背景与问题

普通大模型通常会把不同考虑整合成一份综合回答。回答可能完整，却容易形成单一叙述，用户较难观察不同立场如何冲突、各自依赖哪些条件，以及新信息会怎样改变建议。

人格会议试图解决四个问题。

1. 用户知道自己纠结，却不容易把冲突说清楚。
2. 单一综合回答可能掩盖风险、机会、关系和执行条件之间的差异。
3. 用户补充新情况后，原建议是否仍成立缺少清晰展示。
4. 一次聊天结束后，用户缺少结构化、可回顾的结论。

以下内容仍属于需要验证的产品假设。

- 用户认为多个人格角色的观点差异有价值。
- 开放式讨论比普通 AI 综合建议更容易带来新视角。
- 用户愿意阅读多角色对话，并主动结束讨论、生成纪要。
- 有趣的角色体验能够转化为再次使用和实际行动。

竞品存在不能证明上述需求成立。同一个模型模拟多个人格时，各角色仍可能共享错误和遗漏。MVP 必须通过用户测试验证真实增益。

## 3. 产品目标

### 3.1 MVP 目标

- 让用户在三分钟内发起一场人格会议。
- 让用户在讨论中看到至少两个有实质差异的关注角度。
- 允许用户通过补充条件改变后续讨论。
- 在用户主动结束时生成结构完整、可以回顾的决策纪要。
- 记录趣味性、新视角、行动意愿和再次使用意愿四类反馈。

### 3.2 非目标

- 不提供官方人格测评或心理诊断。
- 不根据少量文字推断用户本人属于哪种人格。
- 不替用户做最终决定。
- 不提供医疗、法律或高风险财务结论。
- 不在 MVP 中提供自动提醒、微信支付、会员套餐或多人真人会议。
- 不训练自有大模型，不把多个角色包装成多个独立专家。

## 4. 目标用户

### 4.1 核心用户

18 岁及以上，平时习惯向 AI 聊天、倾诉或询问建议，并希望看到多个角度的人。

### 4.2 首批重点用户

- 面临选专业、考研、实习、求职或城市选择的学生。
- 面临跳槽、转岗、项目选择或职场沟通的年轻职场人。
- 熟悉四字母人格类型，愿意尝试人格角色互动的用户。

### 4.3 使用场景

- 学习与职业选择。
- 人际关系与沟通困扰。
- 感情和日常生活选择。
- 低风险消费、时间安排与个人计划。

用户可以提出多种生活问题。系统识别到自伤危机、医疗诊断、法律结论、高风险投资或其他高风险场景时，停止人格会议，转入安全引导。

## 5. 产品原则

1. 问题优先。用户可以直接描述困扰，不必先完成长测试。
2. 角色可辨认。角色的表达方式和关注点应稳定，但不能沦为刻板标签。
3. 分歧有依据。角色必须指出自己依赖的条件，不能只表演语气差异。
4. 用户可介入。用户随时可以补充事实、点名角色或结束会议。
5. 结论可回顾。纪要必须保留共识、分歧、未知信息和下一步。
6. 数据可控制。会议自动保存，同时提供清晰的查看和删除入口。
7. 安全优先。风险判断失败时暂停生成，不跳过关键安全检查。

## 6. MVP 范围

### 6.1 必须实现

- 微信授权登录。
- 年龄确认，MVP 仅面向 18 岁及以上用户。
- 快速开始和自选人格两个入口。
- 系统根据问题推荐 4 个人格。
- 用户可以替换角色，并将参会人数调整为 3 至 5 个。
- 开放式人格会议。
- 默认首轮讨论后暂停，等待用户操作。
- 用户插话、补充条件、追问角色、点名发言。
- 总结当前讨论、生成决策纪要和结束会议。
- 自动保存会议记录与纪要。
- 历史会议列表、详情查看和删除。
- 结果反馈采集。
- 内容安全、高风险场景中止和异常降级。
- AI 生成内容标识及必要的隐私、服务说明。

### 6.2 暂不实现

- 人格测试与自动判型。
- 自动回访和微信服务通知。
- 微信支付、会员和次数套餐。
- 语音输入与语音角色。
- 分享到好友、群聊或朋友圈。
- 外部网页搜索、实时新闻或专业数据库。
- 长期用户人格画像和自动性格分析。

### 6.3 为后续预留

- 会议额度和付费套餐字段。
- 模型路由接口。
- 提醒时间和提醒授权字段。
- 角色皮肤、声音和主题配置。

预留仅指数据和接口避免明显阻塞，不要求 MVP 开发空功能或隐藏入口。

## 7. 人格角色体系

### 7.1 角色来源

产品直接使用 INTJ、ENFP 等四字母类型作为人格角色。产品页面需要说明，这些角色是 AI 根据常见类型描述创作的思考视角，不是官方 MBTI 测评结果。

公开名称、宣传文案和视觉资产在上线前进行商标与知识产权审查。产品不得声称获得 Myers-Briggs 或 16Personalities 官方授权，不得复制其受保护的角色形象、文案或测试题。

### 7.2 角色卡字段

- 类型代码。
- 中文角色名称。
- 一句话关注点。
- 擅长提出的问题。
- 容易忽略的部分。
- 表达风格。
- 本场推荐理由。

### 7.3 角色行为约束

- 每个角色围绕当前事实发言，不虚构用户经历或他人心理。
- 角色差异体现在关注点、假设和建议上，不能只靠口头禅区分。
- 角色可以同意、反驳或修正观点。
- 角色不能因为类型标签宣称自己一定正确。
- 角色引用其他发言时，需要指向具体观点。
- 新条件出现后，角色应说明观点是否变化及原因。
- 没有真实分歧时可以形成共识，不强行争吵。

## 8. 核心用户流程

### 8.1 首次进入

1. 用户打开小程序。
2. 页面展示产品用途、AI 内容提示和 18 岁年龄要求。
3. 用户微信授权登录并确认年龄。
4. 用户查看必要的服务与隐私说明。
5. 用户进入首页。

未确认年满 18 岁的用户不能进入会议功能。

### 8.2 快速开始

1. 用户点击“说说你的问题”。
2. 输入问题，可选填写已有选择和最担心的事情。
3. 系统完成风险检查和问题理解。
4. 系统推荐 4 个人格，并显示每个角色的推荐理由。
5. 用户可以直接开始，也可以替换角色或调整为 3 至 5 人。
6. 用户点击“开始会议”。

### 8.3 自选人格

1. 用户点击“自己选人格”。
2. 浏览 16 个人格角色卡。
3. 选择 3 至 5 个角色。
4. 输入问题。
5. 系统完成风险检查。
6. 用户点击“开始会议”。

### 8.4 开放式会议

1. 主持人用一小段话复述问题和已知条件。
2. 若存在会显著改变讨论的缺失信息，主持人一次提出一个问题。用户可以回答或跳过。
3. 参会角色完成首轮发言。
4. 系统暂停，不自动无限续写。
5. 用户选择下一步操作。
   - 继续讨论。
   - 补充情况。
   - 追问某个角色。
   - 请某两个或多个角色讨论指定重点。
   - 总结当前讨论。
   - 结束并生成纪要。
6. 每次继续只生成一个受限讨论单元，完成后再次等待用户。

### 8.5 生成纪要

1. 用户点击“总结”或“结束会议”。
2. 主持人读取最新事实版本和有效发言。
3. 系统生成结构化纪要。
4. 用户可以查看原会议、复制纪要或返回历史列表。
5. 会议状态变更为已结束。

### 8.6 历史记录

1. 用户进入“我的会议”。
2. 按时间查看会议标题、参会人格和状态。
3. 打开会议详情，查看对话和纪要。
4. 用户可以删除记录。

删除必须由用户明确触发。删除成功后，该记录不能继续出现在历史列表或模型记忆中。

## 10. 功能需求

### 10.1 登录与年龄限制

**FR-01 微信登录**

- 支持微信小程序登录。
- 服务端用登录凭证换取用户标识，客户端不保存服务端密钥。
- 登录失败时允许重试并展示清晰错误。

**FR-02 年龄确认**

- 首次进入必须确认年满 18 岁。
- 未确认或明确未满 18 岁时禁止进入会议。
- MVP 不通过猜测生日或聊天内容判断年龄。

### 10.2 问题输入与角色选择

**FR-03 问题输入**

- 问题为必填项。
- 已有选择和最大担忧为选填项。
- 前端显示字数限制，后端再次校验。
- 用户可以在开始前修改输入。

**FR-04 系统推荐**

- 默认推荐 4 个人格。
- 每个推荐必须给出与本场问题相关的一句话理由。
- 推荐不能依据系统自动推断的用户人格。
- 推荐失败时使用覆盖风险、探索、关系和执行角度的默认组合。

**FR-05 自选人格**

- 用户选择 3 至 5 个角色后才能开始。
- 已选择角色有明显状态和数量提示。
- 用户可以查看简短角色说明。

### 10.3 会议编排

**FR-06 主持人复述**

- 开场区分用户明确事实和待确认信息。
- 用户可以纠正复述。
- 纠正后生成新的事实版本，后续发言绑定最新版本。

**FR-07 首轮讨论**

- 每个参会角色至少发言一次。
- 发言应包含观点、依据的条件、一个提醒或建议。
- 单条发言限制长度，默认折叠较长解释。
- 首轮完成后自动暂停。

**FR-08 用户介入**

- 用户可以输入自由文本。
- 用户可以点名一个或多个参会角色。
- 用户可以选择“继续讨论”“换个角度”“总结当前讨论”。
- 非参会角色不能在本场会议中突然发言。

**FR-09 条件更新**

- 用户新增或纠正的信息形成新的事实版本。
- 已经生成的旧发言继续保留，但标明基于旧条件。
- 新发言和最终纪要只使用最新有效版本。
- 旧版本返回结果晚到时不得覆盖新版本结果。

**FR-10 有界生成**

- 每次用户操作最多触发一个讨论单元。
- 每个单元限定发言角色数、单条长度、总输出和调用次数。
- 单元结束后等待用户，不允许模型自行无限循环。
- 达到单场上限时提示用户先生成总结，可新建会议继续。

### 10.4 决策纪要

**FR-11 纪要结构**

- 当前问题与最新条件。
- 主要共识。
- 主要分歧及各自依赖的条件。
- 仍需确认的信息。
- 一个近期可执行的下一步。
- 可能改变结论的条件。

**FR-12 纪要质量**

- 不用多数角色同意证明事实正确。
- 没有分歧时明确写出当前共识。
- 信息不足时提供收集信息的下一步，不编造答案。
- 不输出确定性命运判断或人格标签。

### 10.5 保存与删除

**FR-13 自动保存**

- 微信登录后自动保存会议状态、用户输入、角色选择、讨论和纪要。
- 界面首次使用时明确说明自动保存。
- 保存失败时显示“未保存”，不能假装成功。
- 支持从最近的有效检查点恢复。

**FR-14 历史记录**

- 用户只能读取自己的会议。
- 列表支持进行中和已结束状态。
- 会议标题可由问题自动缩写，用户后续编辑属于非 MVP 功能。

**FR-15 删除**

- 删除前显示影响范围。
- 删除操作要求当前登录态和记录归属校验。
- 删除正文、纪要、关联生成缓存和可检索索引。
- 备份中的清除周期在隐私说明中明确。

### 10.6 反馈

**FR-16 会议反馈**

纪要页使用轻量反馈收集以下项目。

- 讨论是否有趣。
- 是否出现新角度。
- 是否愿意尝试下一步。
- 是否愿意再次使用。

反馈允许跳过。后台按会议匿名统计，不默认把私人问题正文与分析报表绑定展示。

## 11. 内容安全与使用边界

### 11.1 高风险识别

在问题提交、用户追加消息和生成纪要前执行风险检查。至少覆盖以下类型。

- 自伤、自杀、他伤或现实危机。
- 医疗诊断、用药与紧急健康问题。
- 法律定性或具体法律行动结论。
- 高风险投资、借贷、赌博或重大财务操作。
- 违法活动、暴力、色情及其他平台禁止内容。

### 11.2 处理方式

- 自伤或现实危机场景停止角色讨论，使用支持性语言帮助用户联系可信的人和当地紧急支持。
- 医疗、法律和高风险财务问题不生成角色化结论，可以帮助整理一般信息和建议寻求合格专业人士。
- 无法判断风险时暂停并请求必要澄清。
- 关键安全服务不可用时暂停生成，不进入普通会议。

危机响应中的联系方式必须按上线地区核验，不得让模型临时编造。

### 11.3 人格边界

- 不称用户“就是某种人格”。
- 不把类型用于招聘筛选、能力评价或心理诊断。
- 不复制第三方人格产品的专有测试题、插画和文案。
- 明确说明角色由 AI 生成。

## 12. 数据与隐私

### 12.1 数据实体

- 用户账户。
- 年龄确认记录。
- 会议。
- 事实版本。
- 参会人格。
- 消息和发言。
- 决策纪要。
- 用户反馈。
- 脱敏运行事件。

### 12.2 数据原则

- 只收集实现功能所需的数据。
- 自动保存前进行清晰提示。
- 用户可以查询和删除自己的记录。
- 模型请求只发送完成当前步骤所需的上下文。
- 默认指标和错误日志不记录完整问题原文。
- 数据库按用户身份隔离，服务端从登录上下文取得用户归属，不相信模型或客户端传入的用户 ID。
- AppSecret、模型密钥和数据库凭证只保存在服务端。

### 12.3 待确认的数据事项

- 会议记录默认保存期限。
- 删除后备份清除周期。
- 服务部署地区。
- 最终模型供应商的数据留存和训练政策。
- 小程序运营主体及隐私合规责任人。

这些事项确认前，不承诺“永久保存”“绝不留存”或特定的数据跨境结论。

## 13. AI 输出与模型要求

### 13.1 模型策略

MVP 不预先指定模型。后端建立统一模型适配接口，同一批测试用例比较候选模型。

评估维度包括中文自然度、角色差异、观点引用准确性、条件更新能力、结构化输出成功率、安全表现、首字延迟、完整时延和单场成本。

### 13.2 结构化输出

角色发言至少包含以下字段。

- `role_type`
- `claim_id`
- `viewpoint`
- `fact_refs`
- `assumptions`
- `responds_to`
- `change_condition`

纪要使用固定结构校验。格式不合格最多修复一次，仍然失败时交付可读的部分结果并明确缺项，不进行无限重试。

### 13.3 AI 标识

- 会议室持续显示“内容由 AI 生成”或等效显著标识。
- 角色卡明确标注为 AI 人格角色。
- 复制或导出纪要时保留必要的 AI 生成提示。
- 上线材料中如实说明产品提供生成式人工智能服务。

## 14. 状态与编排

建议会议状态如下。

`新建 → 风险检查 → 角色确认 → 主持人澄清 → 首轮生成 → 等待用户 → 讨论单元生成 → 等待用户 → 纪要生成 → 已结束`

辅助状态包括 `生成中、暂停、失败、安全中止、已删除`。

宿主程序负责状态、最大轮次、预算、权限和事实版本。模型负责当前步骤的内容。模型不能自行修改状态、保存授权或用户身份。

开放讨论仍采用固定外层流程。用户每次操作触发一个有限单元，单元完成后回到等待状态。这样既保留开放互动，也控制费用和失控风险。

## 15. 异常与降级

| 异常 | 产品行为 |
|---|---|
| 模型超时 | 有限次数重试；仍失败则保留检查点，允许用户重试 |
| 模型限流 | 展示稍后重试，不连续后台调用 |
| 结构错误 | 修复一次；仍失败则展示部分结果和缺项 |
| 角色观点重复 | 提醒模型从不同约束重新组织一次，不强行制造争吵 |
| 保存失败 | 明确显示未保存，保留当前页面供复制或重试 |
| 登录失效 | 暂停写入，重新登录后校验会议归属 |
| 用户更新条件时旧响应返回 | 丢弃或标记为旧版本，不覆盖最新结果 |
| 安全检查不可用 | 暂停会议，不绕过检查 |
| 达到单场上限 | 引导用户生成纪要或新建会议 |
| 网络断开 | 显示已保存到哪个检查点，恢复后继续 |

## 16. 非功能需求

### 16.1 性能

- 用户发送消息后应尽快出现明确的生成状态。
- 首字延迟和完整生成时间由模型实测后设定正式指标。
- 建议原型目标为首阶段反馈 P95 不超过 15 秒，单个讨论单元机器处理时间 P95 不超过 60 秒。
- 上述数字属于待验证目标，不是已测性能。

### 16.2 可用性

- 用户能够取消正在生成的讨论单元。
- 每次写入使用幂等请求标识，防止重复保存。
- 已完成步骤保存检查点，网络恢复后不必重跑全部会议。

### 16.3 安全

- 客户端不包含微信 AppSecret 或模型密钥。
- 服务端接口进行身份、归属、参数长度、类型和版本校验。
- 防止提示注入改变工具权限和系统规则。
- 删除、注销等操作使用可信产品接口，不交给模型自主调用。

### 16.4 可观测性

- 记录请求 ID、会议 ID、事实版本、阶段、模型配置版本和角色协议版本。
- 记录耗时、Token、结构修复、安全中止、保存失败和用户取消。
- 默认不把用户问题原文写入普通运行日志。

## 17. 微信小程序上线要求

- 准备小程序运营主体、AppID 和必要的管理员权限。
- 完成适用的小程序备案与网络服务备案。
- 后端使用经过备案的 HTTPS 域名，并在小程序后台配置服务器合法域名。
- 准备用户协议、隐私保护说明、AI 生成内容标识说明和投诉反馈入口。
- 根据实际服务能力选择准确的小程序类目，不通过弱化文案规避审核。
- 上线前核验生成式 AI 服务涉及的备案、安全评估、内容标识及模型服务要求。
- 使用第三方模型时，核对其是否允许相应公开服务场景，并签订所需的数据与服务协议。

法规和平台规则会变化，提交审核前需要依据当时官方规则复核。本 PRD 不是法律意见或平台审核保证。

## 18. 技术形态建议

### 18.1 客户端

微信小程序原生框架或成熟跨端框架均可。MVP 需要稳定支持登录、流式或分段显示、长列表、历史记录和网络重连。框架选择在技术设计阶段确定。

### 18.2 服务端

- 登录与用户服务。
- 会议状态机。
- 人格角色配置。
- 模型统一适配器。
- 风险检查与输出校验。
- 会议记录和反馈服务。
- 日志、指标与限额。

### 18.3 数据库

公开测试建议使用支持事务和可靠备份的关系型数据库。人格配置可以版本化存储，用户记录按用户标识隔离。MVP 不需要向量数据库。

### 18.4 Agent Blueprint 组件映射

| 组件 | MVP 决策 | 产品落点 |
|---|---|---|
| s01 Agent Loop | 必选，受限使用 | 单步模型调用和工具结果循环 |
| s02 工具系统 | 必选，最小化 | 本人会议读取、保存及校验工具 |
| s03 权限系统 | 必选 | 用户归属、保存、删除和数据访问控制 |
| s04 Hooks | 必选 | 输入风险检查、输出校验、脱敏事件 |
| s05 任务规划 | 合并实现 | 使用会议阶段状态，不另设自由规划工具 |
| s06 子 Agent | 放弃 | 人格是受控角色模拟，无需自治子 Agent |
| s07 技能加载 | 放弃 | MVP 规则规模较小 |
| s08 上下文压缩 | 必选 | 开放讨论可能变长，保留事实与有效观点 |
| s09 记忆系统 | 必选，简化 | 按会议 ID 保存记录，不自动提取人格画像 |
| s10 任务系统 | 放弃 | 无任务依赖图和多人认领 |
| s11 后台任务 | 放弃 | MVP 无分钟级慢任务 |
| s12 定时调度 | 放弃 | 已确认不做自动提醒 |
| s13 Agent 团队 | 放弃 | 不需要持久队友或隔离工作区 |
| s14 MCP | 放弃 | MVP 不接外部工具生态 |
| s15 集成 Harness | 必选，裁剪 | 统一状态、权限、记忆和钩子 |
| s16 工作流运行时 | 必选 | 固定外层流程、检查点和恢复 |
| s17 目标闭环 | 放弃 | 用户结束或固定上限决定停止 |

## 19. 数据指标

### 19.1 核心指标

- 有效会议完成率。
- 纪要生成率。
- 新视角认可率。
- 下一步行动意愿率。
- 再次使用意愿率。
- 7 日内再次发起会议率。

### 19.2 体验指标

- 趣味性评分。
- 角色区分度评分。
- 用户主动继续讨论的比例。
- 用户补充或修正条件的比例。
- 生成中途退出率。
- 平均每场参会人数和讨论单元数。

### 19.3 质量与安全指标

- 结构化输出一次成功率。
- 角色重复内容率。
- 事实引用错误率。
- 高风险场景拦截召回与误拦截情况。
- 跨用户数据访问事件，目标为零。
- 保存失败率和删除完成率。

## 20. 验证计划

### 20.1 用户测试

邀请 8 至 12 名符合目标画像的成年人，使用真实但非高风险的问题体验。至少覆盖学习职业、人际关系和日常选择。

使用同一个候选模型比较两种体验。

- 普通 AI 综合建议。
- 人格会议。

尽量匹配输入信息、总输出长度和成本，随机或交叉安排体验顺序。分别询问趣味性、新视角、行动意愿和再次使用意愿，避免把“内容更长”误判为“多视角更好”。

### 20.2 探索性继续标准

在至少 8 名完成体验的用户中，建议观察以下门槛。

- 至少 6 人能具体说出一个新增视角。
- 至少 5 人愿意接受或修改纪要中的下一步。
- 至少 5 人表示愿意再次使用。
- 人格会议相对普通 AI 在至少一个核心指标上呈现稳定、可解释的改善。

小样本结果只用于决定下一轮迭代，不能证明市场规模、付费意愿或统计显著优势。

### 20.3 模型测试

建立一套固定测试集，覆盖模糊问题、条件更新、角色冲突、无真实分歧、长讨论、提示注入和高风险场景。每个候选模型使用相同提示词版本、温度范围和输出上限。

## 21. 验收标准

### 21.1 产品验收

- 用户能够通过两个入口成功发起会议。
- 每场可以选择 3 至 5 个人格。
- 首轮完成后系统会暂停并等待用户。
- 用户可以补充条件、点名角色、继续讨论和生成纪要。
- 纪要包含规定的五类核心信息。
- 会议自动保存，用户只能查看自己的记录并能删除。
- 高风险用例能停止普通人格讨论。
- 页面持续展示 AI 生成内容提示。

### 21.2 工程验收

- 缺少配置时服务给出明确错误，不泄露密钥。
- 超时、限流、结构失败和保存失败均有明确状态。
- 条件版本冲突不会让旧响应覆盖新结果。
- 跨用户读取、删除和修改请求被拒绝。
- 关键安全检查不可用时系统暂停生成。
- 脱敏轨迹能够定位失败阶段。
- 数据库备份和恢复流程经过演练。
