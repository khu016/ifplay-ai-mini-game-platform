# 第一阶段技术开发文档｜人格会议网页端（最小纵向切片）

> 配套文档：《人格会议网页端 PRD v1.1》、《第一阶段技术适配声明》、通用技术栈手册。
> 本文档只覆盖第一阶段（对应 AGENTS.md 阶段 2 后端 MVP 的纵向切片）。开发时不得提前实现后续阶段能力。
> 状态：待产品经理确认后开始开发。

## 一、阶段目标

- 交付范围（对齐 D10）：邮箱验证码登录 + 年龄确认、快速开始 / 自选人格、开放式有界会议、决策纪要、自动保存 / 历史 / 删除、反馈、高风险中止、AI 标识。
- 阶段产物：可本地运行的最小纵向切片——后端核心能力 + 一个临时验收页面（非正式前端）。
- 验收标准（对齐 PRD 第 21 节）：能通过两个入口发起会议、每场 3–5 个人格、首轮后暂停、可补充/点名/继续/纪要、纪要含五类信息、自动保存且只能看自己的并可删除、高风险能中止、页面持续有 AI 标识。
- 明确不做：人格测试、自动提醒、支付/会员、微信小程序、语音、分享、外部搜索、长期用户画像、正式前端视觉系统。
- 本阶段打通的主链路片段：登录 → 确认年龄 → 输入问题 → 推荐/自选人格 → 开始会议（主持人复述 + 澄清 + 首轮）→ 用户继续/补充/追问 → 单讨论单元（SSE 流式）→ 生成纪要 → 历史查看/删除。

## 二、技术适配摘要

- 引用结论：开发路径 = 纵向切片（多轮对话 + 人工确认是核心能力，必须带最小真实界面）。
- 采用默认方案：Python 3.12 + FastAPI + Pydantic + pytest + Git。
- 启用按需模块：SQLAlchemy + Alembic（关系型数据，开发期 SQLite）、SSE（流式发言）、模型统一适配器、邮箱验证码发信（开发期 mock）、上下文压缩（保留事实与有效观点）。
- 偏离/暂缓：正式前端 Next.js 暂缓（阶段 3），阶段 2 用单 HTML 验收页；生产 PostgreSQL 暂缓（阶段 4）；邮件服务商暂缓（开发期 mock）。

## 三、技术栈与模型

- 后端：Python 3.12.x、FastAPI、Pydantic v2、SQLAlchemy 2.x、Alembic、pytest、uvicorn。
- 前端（验收页）：单个 HTML + 原生 JS + fetch/SSE，挂在 `backend/static/`，不引入前端脚手架。
- 模型：先接 DeepSeek（OpenAI 兼容接口、中文自然度好、成本低），通过统一适配器接入；适配器预留通义千问、智谱 GLM，供后续（v0.3）做对比测试。开发期无 Key 时全部 mock。
- 明确不引入：向量数据库、任务队列、对象存储、Redis、OCR、小程序 SDK。

## 四、环境与配置

- 配置项（`.env.example`，无秘密）：
  - `MODEL_PROVIDER` / `MODEL_NAME` / `MODEL_API_KEY` / `MODEL_BASE_URL`
  - `DATABASE_URL`（默认 `sqlite:///./data/app.db`）
  - `SESSION_SECRET`
  - `SMTP_*`（邮件，开发期可不填，走 mock）
  - `DEV_EMAIL_CODE`（开发期验证码直显开关）
- 需要用户提供：真实模型 API Key（验收前提供即可，无 Key 不阻塞开发，只阻塞真实冒烟）。
- 启动端口：默认 `8000`；与现有项目冲突时改用替代端口并记录。
- 需要先装：Python 3.12（系统仅有 3.9.6，`~/.local/bin/python3.12` 为悬空软链，开工第一步先装 3.12 或建 3.12 虚拟环境）。

## 六、数据、资产与状态

持久化方式：关系型数据库 SQLite（开发期）+ SQLAlchemy + Alembic（多实体关系、事务、按用户隔离触发）。

数据表（字段与说明）：

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| users | id、email、age_confirmed、created_at | 用户账户 + 年龄确认 |
| verification_codes | id、email、code_hash、expires_at、used_at | 邮箱验证码（哈希存储，不存明文） |
| meetings | id、user_id、title、status、current_fact_version_id、deleted_at、created_at、finished_at | 会议主表，软删除 |
| fact_versions | id、meeting_id、version、question、known_choices、concerns、created_at | 事实版本（条件更新） |
| participants | id、meeting_id、role_type、sort | 本场参会人格（3–5 个） |
| messages | id、meeting_id、fact_version_id、speaker、role_type、claim_id、viewpoint、fact_refs、assumptions、responds_to、change_condition、created_at | 消息与角色发言（结构化） |
| summaries | id、meeting_id、problem_and_conditions、consensus、disagreements、unknowns、next_step、change_conditions、created_at | 决策纪要 |
| feedbacks | id、meeting_id、interesting、new_perspective、next_step_intent、reuse_intent、created_at | 匿名反馈（不绑定问题原文展示） |

状态机（PRD 第 14 节）：

`新建 → 风险检查 → 角色确认 → 主持人澄清 → 首轮生成 → 等待用户 → 讨论单元生成 → 等待用户 → 纪要生成 → 已结束`
辅助状态：`生成中、暂停、失败、安全中止、已删除`。

- 宿主代码管理状态、最大轮次、预算、权限、事实版本；模型只负责当前步骤内容，不得改状态。
- 事实版本：新增/纠正信息产生新版本，旧发言保留但标记基于旧版本；最新有效版本用于新发言和纪要；旧版本响应晚到不覆盖新版本。
- 检查点：每一步完成后持久化，网络恢复/刷新后从最近有效检查点继续。

## 七、API / 工具设计

统一错误结构：`{"error": {"code", "message"}}`，不泄露堆栈。前缀 `/api/v1`。

| 方法 | 路径 | 用途 | 关键请求 / 响应 |
| --- | --- | --- | --- |
| POST | /api/v1/auth/request-code | 发邮箱验证码 | 请求 `email`；开发期返回 mock 提示 |
| POST | /api/v1/auth/verify | 验证码登录 + 年龄确认 | 请求 `email、code、age_confirmed`；响应设 HttpOnly Cookie 会话 |
| POST | /api/v1/auth/logout | 退出 | 清除会话 |
| GET | /api/v1/me | 当前用户 | 返回 email、age_confirmed |
| GET | /api/v1/personas | 16 个人格角色卡 | 返回角色卡字段列表 |
| POST | /api/v1/meetings | 创建会议（快速/自选） | 请求 `question、known_choices、concerns、mode、role_types[]`；返回会议 + 推荐角色 |
| GET | /api/v1/meetings | 历史列表 | 返回自己的会议（标题、人格、状态） |
| GET | /api/v1/meetings/{id} | 会议详情 | 校验归属 |
| DELETE | /api/v1/meetings/{id} | 删除 | 校验归属，软删除正文/纪要/索引 |
| POST | /api/v1/meetings/{id}/recommend | 推荐 4 人格 | 失败回退默认组合（风险/探索/关系/执行） |
| POST | /api/v1/meetings/{id}/start | 开始会议 | 主持人复述 + 澄清 + 首轮，之后进入等待用户 |
| POST | /api/v1/meetings/{id}/steps | 用户操作（继续/补充/追问/点名/换角度/总结） | SSE：`chunk`(0..n) → `done`(完整结果) 或 `error`(统一错误) |
| POST | /api/v1/meetings/{id}/summarize | 生成决策纪要 | 结构化纪要，校验失败修复一次 |
| POST | /api/v1/meetings/{id}/finish | 结束会议 | 状态 → 已结束 |
| POST | /api/v1/meetings/{id}/feedback | 反馈 | 四项可跳过，匿名统计 |

- 长耗时（讨论单元生成）用 SSE；会议详情/纪要等普通操作用同步接口。
- SSE 事件：`chunk` 零到多次 → 以 `done`（含完整结构化结果）或 `error`（统一错误结构）收尾，二者必居其一；流中途失败必须 `error` 收尾，不得静默断流。
- 工具白名单（s02）：仅「本人会议读取 / 保存 / 校验」；删除、注销等走可信产品接口，模型不可自主调用。

## 八、Prompt 设计

每份 Prompt 独立文件，可版本追踪。角色发言统一要求结构化输出字段（PRD 13.2）：`role_type、claim_id、viewpoint、fact_refs、assumptions、responds_to、change_condition`。

| Prompt | 角色 | 输入变量 | 输出要求 |
| --- | --- | --- | --- |
| risk_check | 安全 | 用户输入 | 判定是否高风险；自伤/危机/医疗/法律/高风险财务 → 中止；无法判断 → 澄清 |
| recommend | 推荐 | 问题、16 角色卡 | 推荐 4 个 + 每角色一句本场相关理由；不得推断用户人格 |
| host_opening | 主持人 | 问题、已知条件 | 复述 + 区分事实/待确认 + 最多一个澄清问题 |
| role_first_round | 各角色 | 问题、事实、角色卡 | 每角色发言一次：观点 + 依据条件 + 提醒/建议 |
| role_unit | 各角色 | 最新事实、有效观点、用户操作 | 一个有限讨论单元，含条件更新时说明观点变化 |
| summarize | 主持人 | 最新事实、有效发言 | 纪要：问题与条件/共识/分歧及条件/未知/下一步/改变结论的条件 |

- 输出校验：模型输出标准格式 + 后端宽容解析（兼容 `#` 标题、中文序号、点分编号等常见写法）+ Pydantic 强校验；校验失败修复一次，仍失败交付可读部分结果并标缺项，不无限重试。
- 数量/内容约束（如「3–5 条」「每章若干」）不遵守记为瑕疵交产品经理判断，不反复重试烧钱。
- 角色差异体现于关注点/假设/建议，不靠口头禅；不虚构用户经历或他人心理；不输出人格标签或命运判断。

## 九、验收界面或纵向切片

- 需要最小界面：是（多轮对话 + 人工确认是核心能力，纯 JSON 无法判断质量）。
- 性质：临时验收工具（单 HTML），不是正式产品切片。
- 功能上限清单：登录/年龄确认、输入问题、看推荐/自选角色、会议对话流式显示、快捷操作（继续/补充/追问/点名/总结/结束）、纪要查看/复制、历史列表/详情/删除、反馈。
- 目标终端：桌面 + 移动端宽度（响应式基础布局）。

## 十、测试要求

第一层 mock 自动化测试（离线可跑，重点）：

1. 登录与年龄确认：未满 18 / 未确认禁止进入会议；验证码过期/错误/重放。
2. 风险检查规则（确定性单测）：自伤、医疗、法律、高风险财务、违法内容分别命中中止。
3. 状态机流转：非法跳转被拒；首轮后必须暂停；达到单场上限引导生成纪要。
4. 推荐失败回退默认组合（风险/探索/关系/执行）。
5. 角色发言解析器（纯函数单测重点）：标准格式、`#` 标题、中文序号、点分编号、缺字段、字段超量。
6. 纪要结构校验：缺项时交付部分结果并标注。
7. 保存/历史/删除/归属隔离：跨用户读取、删除、修改被拒绝（目标零）。
8. 条件更新：旧版本晚到不覆盖新版本。
9. 错误路径：无 Key / 错 Key 时 SDK 初始化失败走统一 `error`，不泄露密钥与堆栈。

第二层真实模型端到端冒烟（验收前必做，无 Key 时如实写「待验」）：

- 用真实 Key 跑通一条完整链路：创建会议 → 推荐 → 首轮 → 一个讨论单元 → 纪要 → 历史可见。
- SSE 计时（curl -N）：首字时间、`done`/`error` 收尾正确、失败错误结构统一。
- 无 Key/错 Key 的真实表现。
- 用 5–10 条真实样例给产品经理打分，定质量线（D2「待样例打分」→ 落 D2/D3）。
