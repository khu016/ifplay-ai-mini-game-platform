# 技术适配声明

> 项目：人格会议网页端
> 日期：2026-09-16
> 阶段：阶段 1 技术适配（开工前声明，尚未开发）

## 1. 产品形态判断

- 产品类型与核心任务：多轮对话式 AI 产品。用户输入困扰问题，选 3–5 个四字母人格角色，围绕问题做开放式讨论（有界、分步），结束时由主持人整理决策纪要。
- 核心交互：多轮对话 + 分阶段确认（首轮后暂停、每次仅一个有限讨论单元、用户主动继续/补充/追问/结束、纪要可回看）。
- 开发路径：**纵向切片（路径 B）**。理由：本产品核心价值就是「多角色对话 + 用户随时介入」的多轮交互，仅靠后端 JSON 无法判断「多角度回复是否有价值」，必须带一个最小真实界面做端到端验证。
- 当前阶段范围：阶段 2 = 最小纵向切片（最小后端 + 最小验收界面），交付 v0.2 可用 MVP 核心链路；正式响应式前端在阶段 3。

## 2. 采用的默认方案

| 方案 | 采用原因 |
| --- | --- |
| 后端 Python 3.12.x + FastAPI | 与线上运行时一致，适合把会议状态机、模型调用做成可测试 API |
| Pydantic | 校验接口输入和模型结构化输出 |
| pytest | mock 自动化测试 + 错误路径 |
| Git | 沿用外层仓库，本目录不新建嵌套仓库 |
| 前端终端 = 响应式 Web | 阶段 3 用 Next.js + TypeScript + Tailwind CSS；阶段 2 先用最小验收界面（单个 HTML 挂 FastAPI，原生 JS + fetch/SSE） |

| 模块 | 触发条件 | 当前阶段是否引入 |

| 关系型数据库 SQLAlchemy + Alembic | 多用户账户、会议记录、历史、删除、按用户隔离 | 是；开发期 SQLite，生产评估 PostgreSQL |

| 模型统一适配器 | D4 定「国内厂商统一接口对比」 | 是；自建薄适配层 |
| 邮箱验证码发信 | D5 定「邮箱验证码登录」 | 是；开发期可 mock，具体邮件服务商阶段 2 定 |
| 上下文压缩（s08） | 开放讨论变长，需保留事实与有效观点 | 是；业务能力，阶段 2 设计 |
| 向量数据库 / 任务队列 / 对象存储 / OCR / 小程序 SDK | 无对应需求 | 否（PRD 18.3 明确 MVP 不需要向量库） |

## 4. 偏离或暂缓的默认方案

| 默认方案 | 处理 | 原因 | 影响 | 恢复条件 |

| 正式前端 Next.js | 暂缓到阶段 3，阶段 2 用最小验收界面 | 核心链路未验证前不过早铺开正式前端 | 阶段 2 无正式视觉，只有临时验收页 | 阶段 2 核心链路验收通过 |
