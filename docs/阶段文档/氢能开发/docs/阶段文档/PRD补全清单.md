## 已发现的矛盾与不成立的推断

1. **采纳指标不能证明内容质量。** PRD 将编辑后的确认也算采纳，且成稿必经确认可能导致九章全部确认，因此该指标可能为 100% 而原始内容质量仍低。第二部分按章节算，七部分按事件总数算也不一致；重试、重复确认会改变事件分母。建议独立记录流程完成率，以及按报告/章节/生成版本去重的原稿采纳和修改情况；专业质量另用真实样例评分，指标定义待确认。
2. **模型调用成本计数不完整。** 九次仅为章节生成；大纲、可能单独的信息提取、可选优化、失败重试及第五阶段检索相关模型也须纳入。全局优化既已定义为可选，不能将其视为每份报告的必选调用。“三个环节各自调用一次”只能解释为调用类型，不是全文总共三次。
3. **大纲 Prompt 与固定九章约束不一致。** “至少包含”允许超过九章，Markdown 输出也与结构化章节树要求不一致。建议由结构校验强制恰好九章并定义结构化输出，Markdown 作为展示/导出形式。
4. **章节标题不能保证正文不重复或数值一致。** 不传前章正文是既定产品约束，应遵守；但标题无法提供已写事实与具体结论，全局优化也只能改善文本，不能保证工程与财务正确性。尤其优化为可选，未优化初稿的质量边界需明确。
5. **权限存在两处冲突。** 详细交互允许管理员分配角色，权限表仅超级管理员可分配；数据范围允许管理员看全部报告，而 AGENTS 规定正式上线用户只能看自己的数据。建议角色分配以权限表为准；跨用户访问在业务授权明确前不实现，不擅自裁决核心隐私边界。
6. **知识库分期与早期手动关联不一致。** 交互要求第五阶段前保留手动勾选，但参考文档上传管理也在第五阶段；前期不存在真实文档来源。建议前四阶段不展示可用参考文档选择，待第五阶段接入真实能力。
7. **文件格式范围不一致。** 功能表与流程说 PDF/Word，非功能需求另含 .txt 和旧 .doc；需确认第五阶段支持范围，不能默默缩小验收。
8. **来源页码不能对所有格式作相同承诺。** TXT 没有固有页码，DOCX 页码取决于排版渲染。建议 PDF 保留真实页码，其他格式使用真实章节/段落定位或经固定渲染确定页码，禁止伪造位置。
9. **“最新政策”无法仅靠任意知识库保证。** 未定义资料更新日期、权威来源和外部联网能力。建议查询显示资料日期及来源，缺最新依据时明确无法确认，不扩大为联网搜索功能。
10. **版本标识不一致。** 标题和基础版本为 v2.0，但变更日志最新为 v2.1；主文件选择已确定，后续可统一文档标识，不影响当前体检。
