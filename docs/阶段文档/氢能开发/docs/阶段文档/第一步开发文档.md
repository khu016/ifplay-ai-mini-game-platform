# 第一步开发文档：创建报告、提取项目信息、生成大纲

日期：2026-09-15。本文是待执行的开发说明，**不是已实现或已验证结果**。
当前授权仅为文档与归档；用户明确恢复开发前，不安装依赖、不测试、不启动服务、不调用模型。

## 1. 本步目标

研究员提供一段脱敏或公开项目描述，系统创建一个可恢复的报告任务，提取已有项目信息，再生成可供人工检查的九章大纲。

主链路：
```text
输入项目描述 → 保存报告任务 → 提取项目信息 → 保存提取结果
             → 生成九章大纲 → 校验完整候选 → 保存有效版本 → 查看大纲
```

本步产物是报告任务、结构化项目信息、九章大纲 JSON 和可阅读 Markdown 文件。
本步不包含逐章正文、Word 导出、正式网页、知识库、全局优化、对话助手、角色权限或云部署。完成后交给用户验收，后续步骤先确认。

## 2. 已确认的业务条件

| 项目 | 已定结论 |
| --- | --- |
| 使用场景 | 本机、单用户，不开放远程访问 |
| 输入隐私 | 仅脱敏或公开资料，允许发送国内第三方模型；不包含内部机密资料授权 |
| 模型厂商 | DeepSeek；用户持有 API Key，项目尚未配置，实际可用性待验 |
| 推荐模型 | `deepseek-flash`，非思考模式；恢复开发前再次核查官方可用性 |
| 费用上限 | 单次报告大纲任务全生命周期不超过 1 元，自然月不超过 100 元；提取、大纲和重试均计入 |
| 结构要求 | 恰好九章，每章 3—5 个子标题 |
| 缺失信息 | 标为待补充，不编造具体参数 |
| 留存 | 本地持久化、重启可恢复，不自动删除；日志不记完整输入 |
| 质量评价 | 5—10 条脱敏/公开真实样例由用户评价，标准待样例打分，不用章节确认率替代专业质量 |

这些决定来自用户此前逐项选择 A；不再重复询问。

## 3. 输入与提取规则

创建请求拟包含 `description` 和可选 `name`。描述长度 10—4000 字符，名称长度 1—120 字符；这是当前草稿接口限制，恢复开发时确认与真实样例兼容。

| 提取字段 | 含义 | 缺失处理 |
| --- | --- | --- |
| `project_name` | 项目名称 | null，展示待补充 |
| `client` | 客户/需求方 | null |
| `technology` | 技术路线 | null |
| `location` | 建设地点 | null |
| `scale` | 建设规模，保留原单位 | null |
| `investor` | 投资方 | null |

只提取描述明确提供的内容，不根据行业常识补齐投资金额、产量、设备型号、政策、财务收益或技术路线。描述中相互冲突的参数不得擅自裁决，须保留待核查提示；提示的结构与展示方案在恢复开发时落实。
原始描述是数据，不允许用户描述中的指令改写输出契约。

## 4. 九章固定结构

| 顺序 | 一级章节 |
| --- | --- |
| 1 | 总论 |
| 2 | 项目背景及必要性 |
| 3 | 市场分析与预测 |
| 4 | 建设方案与技术方案 |
| 5 | 环境保护与安全生产 |
| 6 | 投资估算与资金筹措 |
| 7 | 财务评价 |
| 8 | 风险分析与对策 |
| 9 | 结论与建议 |

每章 3—5 个二级写作要点，结合真实输入。缺少规模、技术路线、投资与财务假设时，对应子标题显示“待补充”。本步的财务评价是待写作框架，不输出未经依据的收益率或可行性结论。

结构示例仅解释字段，不是模型验证结果：
```json
{"chapters":[{"number":1,"title":"总论","subtitles":["项目概况","建设目标","编制依据（待补充）"]}]}
```
以上仅展示一章；有效产物必须包含九章。校验要同时覆盖章数、顺序、标题内容、非空子标题及数量；现有草稿未完整强制标题语义，不能误称已满足全部约束。

## 5. 工程方案与目录边界

采用 Python 3.12、FastAPI、Pydantic、httpx；pytest 与 ruff 用于验证。只提供本机 API/执行入口，用户无需自己安装依赖或敲命令，获准开发后由执行者代跑。
大纲通过 Markdown 预览供用户阅读，不提前制作正式页面。

代码拟按职责分为配置、结构校验、文件存储、模型适配、预算、业务流程、API 和 CLI。已有草稿保留在 `backend/`，恢复开发先检查，不把草稿当可靠成品。
所有业务路径以“氢能开发”目录为根：配置在本项目 `.env`，数据在本项目 `data/`，输出在本项目 `data/exports/<task_id>/`。
不得读取外层工具包或其他 Agent 的 `.env`；不得继承其他项目同名环境变量导致密钥串用。需要显式定义配置来源优先级、项目标识与密钥加载边界；现有 dotenv 草稿仍存在继承进程变量的风险，须在获准恢复后修复与验证。

## 7. 持久化与状态

单用户本机场景拟使用带 `schema_version=1` 的结构化文件，任务路径 `data/tasks/<UUID>.json`，预算账本 `data/budget.json`。
任务保存 ID、名称、原始描述、创建与更新时间、提取结果、状态、历史有效大纲、最近错误和调用次数。

| 状态 | 含义 |
| --- | --- |
| `created` | 创建成功，未调用模型 |
| `extracting` | 正在提取项目信息 |
| `generating` | 正在生成候选大纲 |
| `ready` | 候选校验通过，存在有效大纲 |
| `error` | 本步操作失败，保留旧有效版本 |
| `interrupted` | 上次操作被中断，等待显式重试 |

这里是第一步任务操作状态，不擅自替换 PRD 后续报告整体状态；接入正文前需明确映射和兼容规则。
保存须原子替换并同步落盘；单进程文件锁保护数据目录，多进程使用同一目录时拒绝启动。损坏文件保留并明确报错，不自动覆盖或删除。
重启后识别中断状态，但不得自动重新执行收费调用。旧有效大纲保持可查看，失败候选不能覆盖。未来多用户或并发更新前重新评估数据库。

## 8. 调用与费用约束

每个任务计划包含信息提取和大纲两类模型契约。每类调用前保存状态并预留保守最大费用，然后才发起请求。
预留和结算均持久化，不能通过刷新、断线、重启或单章式重试清零任务预算。已调用但用量不明时保留预留；用量异常超过上界时停止后续调用并核查。
暂时网络错误允许有限重试；认证失败、结构数量违规和质量不满意不自动反复收费。用户主动重试仍受同一任务 1 元上限约束。
输入 token 上界估算、协议开销与最大输出的可靠性须实际验证；预算控制保护的是项目内调用，不能约束同一 API Key 被其他程序使用的费用。
真实调用须用户已授权并本地安全配置 Key、核价状态有效；启动服务与创建任务不自动调用模型或充值。

## 9. API 与错误契约（计划）

| 方法与路径 | 请求 | 成功响应 |
| --- | --- | --- |
| `GET /health` | 无 | 状态、模型、仅布尔值密钥配置状态 |
| `POST /api/v1/tasks` | description、可选 name | 201，完整 Task 结构 |
| `GET /api/v1/tasks/{id}` | UUID | 保存的 Task |
| `POST /api/v1/tasks/{id}/outline` | 显式生成请求 | SSE 事件序列 |
| `GET /api/v1/tasks/{id}/outline.md` | UUID | 当前有效 Markdown 文本文件 |
| `GET /api/v1/tasks/{id}/outline.json` | UUID | 当前有效大纲结构 |
| `GET /api/v1/budget` | 无 | 预估支出/预留、剩余额度与核价状态 |

SSE 约定为零到多个 `chunk`，最后一个 `done` 或 `error`。`chunk` 是未校验候选，只有 `done` 才代表本次成功保存；不得将候选流误当正式大纲。
服务处理的错误必须终止为 `error`；客户端主动断开或进程被强制终止无法保证收到终止事件，需依靠持久化状态查询和恢复，不作不可能的网络承诺。

统一错误结构：
```json
{"error":{"code":"INVALID_MODEL_OUTPUT","message":"候选大纲不符合约定，已有有效版本保留。"}}
```
错误类型包括请求校验、任务不存在/忙、缺 Key、核价未确认、预算不足、认证失败、网络超时、输出截断、结构不符及存储损坏。响应不暴露上游原文、输入、密钥或堆栈。
服务只绑定 127.0.0.1，拒绝外部 Host 和跨来源调用，不启用公开 CORS；恢复开发时检查实际网络边界。

## 10. 恢复开发后的执行顺序

1. 检查迁入的代码、工具路径、Python 与依赖，修复配置来源隔离问题，生成依赖锁文件。
2. 完成创建任务与输入校验；先验证创建动作不会调用模型。
3. 完成项目信息提取；缺失字段不补造，失败有确定错误。
4. 完成流式九章大纲生成、完整校验与有效版本保存。
5. 完成预算约束、错误处理、旧版本保护和进程恢复。
6. 执行必要 mock、Lint、实际重启与本机接口验证；不能用模拟结果替代真实效果。
7. 安全配置氢能项目自己的 Key，运行获准的真实样例，记录性能、估价、结果并交给用户评分。
8. 交付证据与验收表；用户确认后，才讨论下一步。当前不执行以上步骤。

## 11. 验证范围

mock 测试计划覆盖合法创建、请求脱敏、提取缺失信息、九章及数量约束、认证/初始化/超时/断流、有限重试、预算跨重启、损坏处理、旧版本保护、同任务并发与配置串用防护。
另须实际启动和重启验证持久化，不以调用恢复函数代替所有运行验证。
真实模型样例覆盖具体技术路线、不同规模与缺参数输入；虚构示例仅用于功能试跑，不能充当用户亲历或真实业务证据。记录首大纲 chunk、两次调用总耗时、每类调用用量、重试情况和费用估算。
PRD 性能目标：首字 <5 秒、大纲 <30 秒。信息提取增加总等待，计时必须从用户触发开始，另报告大纲调用时间；未达标明确列出，不改计时口径掩盖问题。
