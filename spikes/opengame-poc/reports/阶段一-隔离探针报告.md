# 阶段一 · 隔离能力探针报告（修正版）

- 时间：2026-10-02（本版修正了证据口径）
- 环境：macOS 15.5，`sandbox-exec`，Node v24.20.0
- 可复跑脚本：`runner/probe-isolation.mjs`

## 结论先行

**sandbox-exec 的 `allow default` 方案已暂停，不用于执行任意生成代码。**

原因：`allow default` 只禁了网络与文件写，**没有限制文件读**。生成代码（或它 spawn 的子进程）可以读取整个宿主文件系统——包括其他项目的 `.env`、`~/.ssh`、浏览器数据——并通过标准输出进入日志。"只读不泄"不成立。

最小容器隔离方案见 `reports/阶段一-容器隔离方案.md`（安装待你确认）。

## 逐项证据（严格按已验证口径）

| 要求 | 结果 | 已验证 / 未验证 |
| --- | --- | --- |
| 阻断外网 | ⚠️ 仅部分 | ✅ 已验证：DNS 解析失败（`ENOTFOUND`）、HTTPS 请求失败。❌ **未验证：直连 IP TCP**（正式探针仅测了 DNS/HTTPS，不宣称直连 IP） |
| 限制文件写 | ✅ | ✅ 已验证：白名单目录写成功；白名单外 `EPERM` 拒绝 |
| 阻止越权子进程 | ⚠️ 部分 | ✅ 已验证：严格白名单下非白名单二进制 exec 被拒。❌ **严格白名单会让 Node/V8 崩溃**（`LowLevelAlloc` 溢出），无法承载 Node/npm 构建负载 |
| 超时强制终止 | ⚠️ 仅部分 | ✅ 已验证：单个直接子进程 `sleep 60` 约 2s 被 `SIGKILL`。❌ **未验证：完整子进程树（子进程再 spawn 孙进程）被整体清理** |

## 关键结论

1. `sandbox-exec` 在**严格白名单（deny default）**下无法运行 Node（V8 崩溃），因此不能做"逐项 allow"的强隔离。
2. `allow default + 禁网 + 禁写`能跑 Node，但**不禁文件读**，生成代码可读宿主敏感文件并借日志外泄——不可接受。
3. 因此第二轨"隔离代码生成→构建→测试→审核"**不能依赖 sandbox-exec**，必须用最小容器（Colima/Docker）实现文件系统、网络、进程、资源的整体隔离。
